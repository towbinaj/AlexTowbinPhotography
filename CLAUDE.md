# CLAUDE.md — Alex Towbin Photography

Conventions for working in this repo. **This repo is public.** Read
`HANDOFF.md` for current status, history, and open items.

## What this is
A self-updating photography portfolio on GitHub Pages:
https://photo.alextowbin.com/ (custom domain; was
https://towbinaj.github.io/AlexTowbinPhotography/, which now redirects)

A GitHub Action (`.github/workflows/deploy.yml`) runs hourly (:17), on every push to
`main`, and on demand. It runs `scripts/build.py`, which pulls photos from the
owner's iCloud shared album, processes them, and builds a static site into
`_site/`, which is deployed to Pages. Photos are **never committed**.

## Privacy & secrets — non-negotiable
- **Never commit the album link/token.** It lives only in the repo secret
  `ICLOUD_ALBUM` (the full `https://photos.icloud.com/shared/album/<token>` URL).
  Don't put it in code, tests, docs, commit messages, or fixtures.
- **Never commit the owner's email or iCloud IDs.** The CloudKit resolve
  response contains the owner's name, email, `ownerRecordName` (`_…`), zone
  names, and short-lived access tokens. Use synthetic values in tests
  (`_owner`, `SharedCollection-TEST`, `example.org`).
- Secret-scan every diff before committing, e.g.
  `git diff --cached | grep -nE "icloud.com/shared/album/0|@hotmail|@gmail|SharedCollection-[0-9A-F]"`.
- `.cache/` (originals during a build, processed images in `.cache/rendered/`)
  and `_site/` are git-ignored; keep it that way.

## Owner preferences (decided — don't relitigate)
- **White photo borders stay.** They're part of the art.
  `trim_white_borders` is `false`; never crop, re-frame, or `object-fit: cover`
  a photo in a way that cuts the border. Show framed prints whole.
- **Copyright matters.** Keep the visible notice ("© <years> Alex Towbin. All
  rights reserved."), the rights metadata (meta tags, JSON-LD, EXIF/XMP in
  every image), and the save deterrents (no right-click, drag, or iOS
  long-press). Don't add download buttons.
- **Low maintenance.** The owner's only workflow is adding and removing photos
  in the shared album. Don't add steps that need manual upkeep (e.g. expiring
  API tokens).
- **Photo titles and order are set in the editor app** (`site/edit/`, owner's
  phone; the old `#edit` mode was removed). It uses a fine-grained GitHub key
  (Face ID-locked, encrypted where the device supports it) scoped to the **data repo**
  `towbinaj/AlexTowbinPhotographyData` only. A **second, optional publish key**
  (site repo only, Actions: read and write) powers the app's *Publish now*
  (workflow_dispatch); keys can't have per-repo permissions, so never merge
  the two. Saves write `curation.json`
  (`{titles, order, collections, highlights, tags, photo_tags, locations}`) there via the GitHub API; the page reads it live from
  raw.githubusercontent.com and the build bakes it in (CI checks it out into
  `data/`). Treat it as untrusted input (validate, render as text only). Unplaced (new) photos sort first. Titles are optional: untitled photos show the date. Apple
  captions/comments are not reachable through the public album link (tested).
  Never put a key in the repo or the build. Titles are title-cased by both
  `title_case()` (build.py) and `site/titlecase.js`; keep them identical
  (shared cases in `tests/titlecase_cases.json`).
- **Show on site:** `hidden` / `published` / `drafts_from` in curation.json;
  photos added after `drafts_from` start hidden (owner chose this). Hidden =
  unlisted, not private (owner chose instant release over privacy): still in
  photos.json with `draft: true`, but left out of the gallery, JSON-LD and
  og image. Rule in `site/meta.js` `isShown()` = `is_shown()` in build.py.
- **Locations are city / state-region / country only** (owner's rule). Never
  store or publish coordinates or anything finer; picks come from the
  built-in GeoNames list so names stay standard. The `located` flag (photo
  file has GPS) is yes/no only.
- **Instagram (@towbinaj)** is linked, not embedded. A live feed needs a
  Meta token that expires every 60 days, which was rejected.
- Design: dark, editorial, modern. Not a template look.

## Layout
```
config.json                 site settings (name, tagline, about, sort, copyright, data_repo…)
data/                       (git-ignored) checkout of the data repo with curation.json
scripts/build.py            iCloud fetch → image processing → _site/
site/index.html|style.css|app.js|titlecase.js|robots.txt   static front end (no framework, no build step);
                            index.html is the template for 4 pages (/, work/, collections/, about/; PAGES in build.py)
site/meta.js                tags + places: cleaning/labels, shared by site and app; mirrored in build.py (parity-tested)
site/edit/                  phone editor app (index.html, edit.js, model.js = pure data logic, tested via node)
site/edit/places.json       built-in places list (GeoNames CC BY), generated by scripts/make_places.py
site/photo.html|photo.css   template for per-photo share pages (_site/p/<id>/), no scripts
tests/test_icloud.py        offline tests (fake iCloud responses; no network)
.github/workflows/deploy.yml  test → build → deploy to Pages
```

## Dev commands
```
pip install -r requirements.txt pytest
python -m pytest -q tests                        # keep green; CI runs it before building
python scripts/build.py --demo 30                # placeholder images, no network
ICLOUD_ALBUM='<link>' python scripts/build.py    # real build (needs iCloud network access)
python -m http.server -d _site 8000
```
GUI checks: use Playwright (preinstalled in cloud sessions) for screenshots at
desktop (1440×900) and phone (`devices['iPhone 13']`) sizes. Look for page
errors, horizontal overflow, and the lightbox flow. Keep these scripts in the
scratchpad, not the repo.

## The build schedule is best effort
GitHub runs the hourly `schedule:` trigger only when it has capacity and
skips many slots (sometimes all of them for hours), with no notice. Every
build that runs succeeds; there's nothing to fix in the workflow. The owner's
reliable path is **Publish now** in the editor app (workflow_dispatch).
An earlier theory that edits pushed through the Claude connection disable
the schedule turned out wrong: a scheduled run fired after a Claude edit on
2026-11-19 with no owner re-save. Owner re-saves are harmless but not needed.

## Conventions
- Engine logic gets offline tests. Never hit the network in tests.
- Front end: plain HTML/CSS/JS. Respect `prefers-reduced-motion`. It must work
  at phone width with no horizontal scroll.
- Update `README.md` when behavior or settings change.
- A push to `main` deploys the live site. Work on a branch unless the owner
  says to push to `main`.
